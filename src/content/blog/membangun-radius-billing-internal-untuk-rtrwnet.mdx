Di banyak ISP kecil dan RTRWNet, billing dan autentikasi pelanggan biasanya bergantung pada aplikasi vendor berbayar. Lisensinya tidak murah untuk skala bisnis lokal, dan fiturnya sering tidak fleksibel mengikuti kebutuhan operasional. Artikel ini merangkum bagaimana saya membangun penggantinya: sistem RADIUS + billing internal yang sekarang melayani 2.000+ pelanggan aktif di production — dan menghemat sekitar Rp12 juta per tahun.

## Masalah

Kondisi awal yang ingin diselesaikan:

- **Biaya lisensi vendor** yang berulang setiap tahun, untuk fitur yang sebagian besar tidak terpakai.
- **Provisioning manual** — aktivasi, isolir, dan perubahan paket pelanggan dikerjakan satu per satu di router.
- **Data tersebar** — data pelanggan, tagihan, dan status koneksi tidak ada di satu tempat.

## Arsitektur

Komponen utamanya sederhana dan semuanya open source:

```
Pelanggan (PPPoE)
      │
MikroTik RouterOS ──► FreeRADIUS (AAA) ──► MySQL
                              ▲
                    Aplikasi Billing (Laravel)
```

- **MikroTik RouterOS** sebagai NAS (Network Access Server). Pelanggan terhubung lewat PPPoE, dan setiap sesi diautentikasi ke RADIUS — bukan ke secret lokal di router.
- **FreeRADIUS** menangani AAA (Authentication, Authorization, Accounting) dengan backend MySQL (`sql` module). Profil kecepatan dikirim sebagai atribut `Mikrotik-Rate-Limit`, jadi perubahan paket cukup update di database.
- **Laravel + MySQL** sebagai aplikasi billing: manajemen pelanggan, generate tagihan bulanan, pencatatan pembayaran, dan status layanan.
- **Nginx + Docker** untuk serving dan isolasi aplikasi, berjalan di Linux server di atas Proxmox VE.

## Alur billing → jaringan

Bagian paling penting adalah menghubungkan status tagihan dengan status koneksi secara otomatis:

1. Scheduler Laravel generate tagihan setiap awal periode.
2. Saat jatuh tempo terlewati, sistem mengubah profil pelanggan di tabel `radgroupreply` ke profil isolir (redirect ke halaman pemberitahuan).
3. Sesi PPPoE aktif diputus lewat RADIUS Disconnect (CoA/PoD), sehingga pelanggan langsung masuk mode isolir tanpa menunggu re-connect.
4. Setelah pembayaran tercatat, proses yang sama berjalan terbalik — pelanggan aktif kembali dalam hitungan detik, tanpa disentuh manual.

Dengan pola ini, tidak ada lagi "lupa isolir" atau "lupa buka isolir" — dua sumber komplain paling umum di operasional RTRWNet.

## Pelajaran yang saya ambil

- **Accounting RADIUS itu emas.** Data `radacct` (durasi sesi, usage per pelanggan) sangat berguna untuk troubleshooting — misalnya mendeteksi pelanggan yang sesinya flapping karena masalah kabel/ODP.
- **Mulai dari skema database vendor-neutral.** Struktur tabel FreeRADIUS standar (`radcheck`, `radreply`, `radgroupcheck`, `radgroupreply`) membuat sistem mudah diaudit dan tidak mengunci ke satu aplikasi.
- **Otomasi bertahap.** Saya mulai dari autentikasi saja, lalu billing, lalu isolir otomatis. Sistem production tidak perlu (dan tidak boleh) diganti sekaligus.

## Hasil

- 2.000+ pelanggan aktif terautentikasi lewat FreeRADIUS di production.
- Biaya lisensi vendor ±Rp12 juta/tahun hilang sepenuhnya.
- Aktivasi, isolir, dan perubahan paket berjalan otomatis — pekerjaan manual berulang di router praktis hilang.

Kalau kamu mengelola RTRWNet dan masih membayar lisensi billing tahunan, stack FreeRADIUS + MySQL + framework web apa pun yang kamu kuasai adalah alternatif yang sangat layak. Silakan hubungi saya kalau mau berdiskusi soal implementasinya.
